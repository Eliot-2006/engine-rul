# EngineRUL results dashboard

A static, single-page dashboard (Vite + TypeScript + [Observable Plot](https://observablehq.com/plot/)) that
shows the committed EngineRUL results. It has no backend, needs no model or MLflow at runtime, and
reads only the JSON written by `engine-rul export-dashboard`.

```bash
make dashboard-data                     # or: uv run engine-rul export-dashboard
cd dashboard && npm ci
npm run dev                             # http://localhost:5173/engine-rul/
npm run check                           # TypeScript type check
npm run build                           # dashboard/dist + scripts/check-dist.mjs
npx playwright install chromium         # once
npm run e2e                             # Playwright browser tests against dashboard/dist
```

`make dashboard` and `make dashboard-test` run the same steps from the repository root.

## Data

`engine-rul export-dashboard` (`src/engine_rul/dashboard.py`) reads `results/final/` and
`results/phase2/`, validates them (required fields, finite numbers, known model identifiers,
complete engine coverage, Phase 2 manifests certifying `official_test_set_used: false`), and writes
small JSON files to `dashboard/public/data/` (git-ignored; CI regenerates them):

| File | Protocol | Source |
|---|---|---|
| `official_test.json` | `official_test` | `results/final/summary.json`, `test_predictions_median_seed.csv` |
| `phase1_validation.json` | `phase1_validation` | `results/final/val_dense_predictions_median_seed.csv` |
| `cv.json` | `nested_cv` | `results/phase2/cv/fd001_nested_cv/` |
| `ablation.json` | `nested_cv_ablation` | `results/phase2/ablation/fd001_ablation/` |
| `conformal.json` | `nested_cv_conformal` | `results/phase2/conformal/fd001_conformal/` |
| `benchmarks.json` | `benchmark` | `results/phase2/benchmark/fd001_latency/`, `results/final/benchmarks.json` |
| `meta.json` | `meta` | model labels, disclaimer |

Each file holds exactly one evaluation protocol. The frontend's loader (`src/data.ts`) checks the
`protocol` field against the chart that asked for it, so official-test and validation-only numbers
cannot be mixed by accident; a missing or mismatched file shows an error in that section only.

## Tests

`scripts/check-dist.mjs` (run by `npm run build`) checks the bundle itself: every local asset sits under
the `/engine-rul/` base path, all seven data files carry the expected `protocol`, the canonical URL,
Open Graph and Twitter tags point at the bundled 1200×630 `og.png`, and the bundle stays under 1.5 MB.

`e2e/dashboard.spec.ts` (Playwright, Chromium) drives the production build served by `vite preview`
under `/engine-rul/`. Expected values are read from `dist/data/` plus literal anchors from the
published evaluation (13.26 cycles, −63.9%, 100 engines, 13 / 15 folds). It covers: loading every data
file without uncaught exceptions or console errors; headline cards, model names and protocol badges;
the RMSE / MAE / NASA-score switch; showing and hiding models; engine selection by menu and by clicking
a scatter point; validation-trajectory switching; the cross-validation, ablation, uncertainty and
benchmark controls; no horizontal overflow or overlapping controls at 375, 768 and 1440 px; navigation
links, the skip link, arrow-key radio groups and accessible names; reduced motion; and the error states
for a missing file (HTTP 404), a file with the wrong protocol and malformed core data. Tests tagged
`@mobile` also run on a 375-px touch viewport.

After a deployment, `E2E_BASE_URL=https://eliot-2006.github.io/engine-rul/ npm run e2e` runs the same tests
against the live site (they read expected values from the local `dist/data/`, so build from the same commit).

## Deployment

`.github/workflows/pages.yml` regenerates the data, type-checks, builds and checks the bundle, then runs
the Playwright tests against that exact build (`e2e` job) on every pull request. Pull requests never
deploy; pushes to `main` deploy `dashboard/dist` to GitHub Pages only after the `e2e` job passes. The site is served
from `/engine-rul/` (`vite.config.ts`; override with `DASHBOARD_BASE=/` for a root deployment).
One-time repository setting: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Design notes

Colours follow a colour-vision-deficiency-checked palette (learned models in blue / orange / aqua,
baselines in neutral greys), with separate steps for dark mode. Every chart has hover tooltips and an
accessible name; tables accompany the main charts, and every chart can also be driven from labelled
form controls. Segmented controls follow the ARIA radio-group pattern (one tab stop, arrow keys), and
smooth scrolling is turned off under `prefers-reduced-motion`. Dependencies are pinned exactly in
`package.json` / `package-lock.json`.

The link-preview image `public/og.png` is generated by `engine-rul readme` from
`results/final/summary.json` (`dashboard.social_card`), alongside the README hero figure. The
`index.html` description and Open Graph / Twitter text quote the headline numbers;
`tests/test_consistency.py` fails if they drift from the committed results.
